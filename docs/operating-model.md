# 運用設計

## 原則

- 収集、検証、成果物作成、公開を混ぜない。
- 情報ごとに原URL、取得時刻、根拠箇所、状態、判断理由を残す。
- 外部公開と金融取引は人の明示承認なしに実行しない。
- 保留には必ず理由と再確認の節目を記録する。

## レビュー台帳

| 列 | 内容 |
|---|---|
| card_id | URLから生成する安定ID |
| theme | 5テーマのいずれか |
| status | 定義済み状態 |
| priority | 機械的な優先順位。人の最終判断ではない |
| source_url | 原典URL |
| evidence_location | 記事見出し、段落、動画時刻など |
| verification | 一次性、重複、反証の確認結果 |
| decision | 採用、保留、破棄、追加調査 |
| decision_reason | 人が判断した理由 |
| next_review_at | 保留・監視対象の次回確認日時 |

## テーマ別の停止点

| テーマ | AIが停止して人へ渡す点 |
|---|---|
| 生成AI | 一次資料でない、定量効果の根拠が不十分、導入推奨へ進む前 |
| マーケティング | 施策提案・対外利用・画像利用の前 |
| 米国メディア | RSS本文の確認、Opinionを事実として扱う前 |
| 日経225 | 開示本文確認前、投資判断へ結びつける前 |
| 為替 | 通貨ペアへの因果付け、取引判断へ結びつける前 |
